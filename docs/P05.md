# P05 : FUSE and RANK

It takes the pile of hypotheses P3 generated and P4 assessed, and turns them into a single ranked, typed list with one winner, a set of alternatives, and a decision about whether to present a single cause or competing hypotheses. Its two jobs are fusion (combine four signals into one H(h) score) and confinement (make sure a weighted score can never resurrect something the validators killed).

## What it does
The entry point is `fuse_investigation()::p5_fuse.py`. Per hypothesis it computes the published four-component score:
```
H(h) = 0.35·D + 0.25·R + 0.20·CC + 0.20·V
```

| Component | Source | Notes |
| --- | --- | --- |
| D | rank_normalized_d over P2's candidate rank | 1.0 for the top-ranked service, 0.0 for the last |
| R | the hypothesis's P3 reward | see caveat below; this is largely suppressed today |
| CC | chain coherence from P4 | 0 / 0.5 / 1 |
| V | validator verdict | pass→1.0, partial→0.5, fail→0.0 |

`fuse_score()` validates the weights are the named components, finite, non-negative, and unit-sum, so there's no hidden function.

Confidence is typed, not chosen. `typed_confidence()::p5_fuse.py` assigns a ceiling from the rule , cross_modal_consensus 0.85, single_modality 0.70, inference_only 0.40 and every cap can only lower it. A vetoed hypothesis gets status disproved/invalid/unvalidated and is never eligible for winner or alternative, no matter how high its weighted score.

The aggregation is where the care shows. Instead of picking a service's single best-scoring sibling, P5 uses stable predeclared slots: for each service it takes the first per_service_slots hypotheses by id, averages only the non-vetoed ones, and lets missing slots contribute zero. A vetoed slot is never replaced by a later successful sibling (`p5_fuse.py`). The winner is the best service by that fixed-slot aggregate; alternatives are the rest (all θ-gated, since a validated/partial status requires ≥ θ evidence strength).

Presentation is chosen by a signal, not a preference: rwr_top3_share(ranking) > 0.7 → single cause, else multi `p5_fuse.py`. That's the RWR mass-concentration rule.

There are four service-ranking policies: deterministic_first_shadow (the default), corrected_h_eligible_first, bounded_p2_update_v1, and conservative_p2_update_v1. The middle two are opt-in reorderings that the default does not apply , by default P5 publishes the P2 baseline alongside shadow scores (eligible, shadow_h_score) without touching the order.

## Conservative association update (opt-in)

`fuse_investigation(..., ranking_policy="conservative_p2_update_v1")`. It concerns
only the P2-derived `service_ranking`, not the H-score winner/alternatives, and
makes **no causal-superiority claim**.

Permission is at most **one adjacent, association-only swap**, and every one of
these must hold: complete untruncated scoped ranking and investigation; exact
scope-bound `assessment_matches` proofs; every predeclared stable-ID challenger
slot present, all-pass, contradiction-free and cross-modal with
`evidence_strength >= 0.85`; an explicit structured claim whose
`claim_applicability` is `pass` (propagation additionally needs a nonempty,
contiguous, fully supported path from anchor to candidate). The displaced
incumbent's fixed slots must each carry an **explicit structured-claim
refutation**. Unknown, absent, unsupported, truncated, provider-failed,
late/inapplicable, missing-path or missing-authority states are *not* permission,
and a missing slot is never rescued by a later sibling.

**It currently always abstains.** P4 exposes no unambiguous refutation
certificate: `claim_applicability` returns the same `fail` for missing direction
metadata and for genuinely opposite direction, other `fail` results can inherit
`svar_lite` failures, and generic `ValidatorRefute` ids can reflect unrelated
vetoes. Rather than infer refutation from those, the policy preserves the P2
order and records why: `FuseResult.config.conservative_update` carries the
abstention reason, both sides' fixed-slot hypothesis/assessment ids, proposal
fingerprints, check ids, the (empty) list of supported positive triggers, and the
one-swap/displacement limits.
