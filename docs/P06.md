# P06 : REPORT

 The API/end-to-end surface the user actually sees. It takes the fused ranking and everything upstream and produces the final artifact: a verdict, a machine-decided confidence tier, deterministic facts, the evidence path, alternatives, an approved runbook and owner, a next action, what was ruled out, what wasn't checked, and cost telemetry.

## What it does
The entry point is `report_investigation()::p6_report.py`. Three things distinguish it:
 
1. It live-re-validates the winner instead of trusting P4. `_live_assessment()::p6_report.py` re-runs assess_hypothesis against the graph now, re-resolves owned_evidence, re-checks claim applicability, and critically requires the live source fingerprints to be unchanged from what P4 recorded. If anything moved, or a structured claim no longer applies, or the evidence is no longer eligible, the winner is dropped to None. So the report describes the graph as it is at report time, not as of P4. Alternatives get the same live ownership check.
 
2. The gate is code, not a prompt. `report/validator.py` The rules:
   - no winner → insufficient_evidence / INCONCLUSIVE
   - validator state must be explicitly pass or partial (an ambiguous False fails closed)
   - confidence/coherence/θ must be finite and in [0,1]
   - confidence < θ=0.6 → INCONCLUSIVE
   - pass and all checks pass and per_link_support → diagnosed / CONFIRMED
   - otherwise → diagnosed / LIKELY, with reasons naming exactly what's missing

3. It finalizes fail-closed. The runner passes final_reads_allowed=False after deadline/resource exhaustion, and in that mode P6 opens no graph handle, does no reads or writes, and calls no provider , it renders the cached state. Any exception in live validation, closure retrieval, or persistence is recorded as a not_checked reason rather than producing a stale diagnosis. If a phase is missing entirely, the runner's `_fallback()::runner.py` emits a purely in-memory INCONCLUSIVE report with zero graph/provider calls.

Everything the model might have written is instead built as facts in `_catalog()::p6_report.py`: the symptom, the decision line (which literally says "mechanism is not established"), each observed anomaly with its z/gamma/direction, every check's verdict and detail, each path edge with "propagation supported/not verified", the owner, and the gaps. The renderer assigns numeric citations mechanically and validates that the citation set exactly matches the evidence ids (it raises on inconsistency).

The runbook comes through the one place P6 uses the tool surface, `t_get_runbook_and_owner::tools.py` then filtered by _approved_closure, so only explicitly approved runbooks yield steps, and commands render as "Approved validation text (not executed)."

On success it persists: an EvidenceGap if there's no candidate, a report Artifact (JSON + markdown), Incident.diagnostic_state/diagnostic_report_version, and for the winner Hypothesis.final_decision = 'eligible' plus ASSOCIATED_WITH.accepted = true.
